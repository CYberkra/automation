### S2 · P2：根进程结束被当成整项任务完成

位置：[bounded_windows_process.py](../../scripts/bounded_windows_process.py) 第 83–98 行。

循环只检查 `proc.poll()`，根进程返回 0 就记为 `completed`；随后关闭设置了 `KILL_ON_JOB_CLOSE` 的 Job，仍在运行的子进程会被终止。CPU 最小复现中，根进程启动一个两秒后写 `child_done.txt` 的子进程并正常退出，监督器约 0.125 秒就返回 `completed / exit_code=0`，子进程完成文件不存在。

复现的子进程行为可表达为：

```python
child = "import time,pathlib; time.sleep(2); pathlib.Path('child_done.txt').write_text('done')"
root = "import subprocess,sys; subprocess.Popen([sys.executable,'-c'," + repr(child) + "]); print('root done')"
# 使用 supervise([sys.executable, '-c', root], <新目录>,
#                wall_s=5, memory_bytes=512*1024**2, output_bytes=1024**2)
```

建议：检查 Job 中的活动进程数，在预算内等待任务树结束；若策略就是终止遗留子进程，应明确记录终止状态，不能无条件报告成功。此项证明的是监督器处理异步子任务的缺陷，**尚未证明现有同步 gprMax 调用因此产生不完整结果**。
