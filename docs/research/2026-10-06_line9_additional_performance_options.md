# 九号线二维仿真的其他加速选项

本轮为日志、安装 V4.0.0 源码和官方文档的只读核查。未启动新求解、未修改网格/精度/时窗、未放行整线。400m/2.5cm/FP64/1200ns 基准保留。已有缩域结果见 [完整域及缩域对照](2026-10-06_line9_full_snapshot_and_crop_findings.md)。

## 实测瓶颈

ROG 完整域 X220 无快照参考：监督器 631.171s，原生求解计时 608.4527s，原生总运行 629.5890s。求解计时之外约 22.7183s，占监督器时间 3.599%。即使完全消除这部分，理想加速也只有 1.03734 倍。求解计时还包含求解循环的调度/输出，不能据此断言 GPU 算术或带宽哪个占主导；需要性能剖析才能分开。

当前已经是 2D TMz。安装源码 `grid/fdtd_grid.py::calculate_dt` 使用二维 CFL，`cuda_opencl/knl_fields_updates.py` 对 NZ=1 不更新 Ex/Ey/Hz；不能把当前运行当成尚未开启二维模式，也不能声称切换二维再省一半。PyCUDA `compiler.py::compile` 默认已有磁盘编译缓存，除非显式禁用；不能假设每道都重新 NVCC 编译全部内核。

## 候选排序及边界

| 候选 | 可能收益 | 当前限制与检查 |
|---|---|---|
| 单精度 FP32 对照 | 可能明显降低显存和运算开销，实际倍数未知 | 改变数值精度，不能直接替换 FP64 基准。先同站同域同源对照真实原始 dtype、501 点复谱及 300–600/600–1200ns 弱窗的幅度、相位、到时；全局 L2 不足以验收。 |
| 保留纵向 2.5cm，仅增大横向网格 | 水平 5cm 时，二维网格量减半，CFL 步长约增 1.2649 倍，核心更新量理论约少至 1/2.5298；水平 3cm 时理论约 1.304 倍 | 均为工作量估算，未经运行。保留完整 400×75m、1200ns、FP64及垂向界面分辨率，仍改变横向几何采样和传播误差。先做原激励完整频带的相位波长/损耗分辨率检查；原 100MHz Ricker 有高频尾，不能只拿 170MHz 的十格/波长认证 5cm 网格，若不合格就淘汰，不绕过 underresolved 门禁。 |
| 固定几何、同进程批处理 | 可节省部分约 3.6% 的求解外开销；求解循环内收益未知 | 官方支持 geometry-fixed，但现有源码每个 model 重建 solver。地形跟随的任意 Tx/Rx 高程需显式位置序列，不能用固定水平步进代替；需证明重置完整、没有跨道场残留。 |
| 多卡/多机分配独立道 | 增加计算资源后可近似分摊整线时间，受负载和 I/O 限制 | 官方 task farm 支持独立模型并行。当前一张 16GiB GPU 不应并发两个完整 FP64 大域任务；需要核验额外设备并分别冻结执行。 |
| 分批先出稀疏 B-scan | 提前看到已计算的测线趋势 | 不减少单道时间、不等价于完整扫描。图上必须标出真实站位及未计算区；不能插值后当成正式密集结果。 |

网格调整时保留物理 PML 厚度约 2m，而不是机械沿用 80 格；水平 5cm 对应 40 格。这也改变离散吸收层，需与几何/长路径一起验证。材料 ID 不做数值平均。原站位坐标不能悄悄取整，需明确网格对齐误差或选可对齐的控制站。

1200→700ns 可减少约 42% 步数，但会改变用于 SFCW 合成的完整响应；现有晚窗和有限频带旁瓣证据不支持直接这样删时窗。统一改 5cm 网格的二维核心更新量理论是 8 倍而非 16 倍，但当前源频带及复杂介质分辨率没有放行，不作为保证质量的快捷方案。减少空气或侧边缓冲同样需要边界对照。

## 建议的最小下一单元

先做候选网格的无求解分辨率/源坐标/PML 预检；与此同时准备一个完整域、完整时窗、原网格的 FP32 独立诊断契约。预检不合格的网格不启动。只对合格候选做 X220 单站对照，全部数值判断保留 FP64 参考，比较弱窗而非仅全局误差；通过后再补其他代表站位。没有测得收益和误差界之前，不承诺整线耗时或“不影响质量”。

本轮没有签发上述执行契约，也没有启动候选求解。专用二维内核、混合精度、CUDA Graphs 等属于更大的求解器工程，需先剖析瓶颈，不作为快速开关。
