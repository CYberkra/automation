# 相关诊断的数值可辨识性与审查修复

本轮接续 `9303298` 的研究，修复[审查报告](../reviews/2026-09-25_review_9303298.md)中的三项问题。用户已授权自主修复、验证后合并并继续工作。本轮只运行 CPU 数组、归档频谱比较和进程控制测试，没有新 FDTD、训练或实测读取。

## 1. 评价与标签的新增约定

当前仍使用评价与标签 v0.2 的 D/A/H、可行性、偏序及集合规则；物理阈值保持未定。附加[方向诊断契约 v0.1](../../configs/research/direction_diagnostic_contract_v0.1.json)，不替换原公式，也不修改原始结果或历史哈希。

`waveform_metrics` 新参数 `direction_error_bound` 表示**固定评价窗内处理输出的 L2 绝对误差预算**，单位随输入幅值；它不是单样本阈值、相对误差、物理噪声门限或置信概率。调用者负责给出预算依据。

| 条件 | 相关诊断 | 其他指标 |
|---|---|---|
| 未提供预算（默认 `None`） | `signed_cosine=null`，记录 `direction_error_bound_not_declared` | 保留 D/A/H 等 |
| 输出严格为零 | `null`，记录 `zero_output` | 删除损伤仍可计算 |
| 输出范数不大于预算 | `null`，记录 `output_direction_numerically_unresolved` | 保留 D/A/H 等 |
| 输出范数大于所声明预算 | 计算相对于给定参考数组的余弦 | 仍不代表物理精度认证 |
| 显式预算为零 | 仅表示调用者采用精确数组假设 | 不能自动套在 SVD、相消或 FDTD 输出上 |

条件依据是本项目使用的简单范数推导：若 `||y_true-y_computed||₂≤e`，当 `||y_computed||₂≤e` 时，允许的误差球包含零向量，方向没有保证；当范数大于 e 时只能排除零向量，**不能据此保证角度误差很小**。更严格的方向误差区间仍需单独建立，参考方向的不确定性也不由这一个输出预算覆盖。这是条件性的数学判断，不是来自文献的 GPR 验收阈值。

本次没有用 `eps × 任意常数` 伪造整条 SVD/相消链的误差界。缺少预算时宁可不报告方向数值；后续需要分别建立输入形成、算子运算、差分相消及参考误差的依据。构造数组的精确值控制例可以显式给零预算；在有明确小预算时，21 项新增检查确认微弱输出及整体换单位不会被统一误判为零。

## 2. 对已归档共同层/目标研究的影响

按当前代码复算 42 行共同层/目标机制诊断，输出另存。本次与旧归档相比，D、幅度系数、幅度损失及 H 的最大绝对变化约 `8.88e-16`，对应浮点环境差异；不改变“全均值可能同时删除地层/目标”的结论。

原 `B5_G1_BG / zfine / localized` 输出只剩相对参考约 `4.77e-16` 的残差，归档相关系数 +0.528 在本机曾变成 −0.498。现在该项不会被当作有效方向证据。由于本批并未建立各算子的输出误差预算，**42 行 × 地层/目标两类共 84 个余弦均明确缺失**，不只删掉看起来不利的某一行。保留各行缺失原因，不能填零后参与均值或排序。

没有因此生成物理标签或训练标签。D/A/R 的配置标签规则不变；过去研究表中的余弦作为历史数值保留，当前解释以本补充为准。

## 3. 执行和归档修复

- 两个 `compare_*` 脚本需要 `--output <新目录>`，拒绝覆盖；导入不执行。归档输入按脚本所在仓库定位，脱离根目录启动也能复算。两份比较 JSON 与旧归档内容一致，旧文件哈希不变。谱比较公式抽到只依赖 NumPy 的模块，归档比较不再因导入辅助函数而要求安装 gprMax。
- 监督器在根进程成功退出后继续检查 Job 活动进程数，等待进程组清空，同时维持时间、内存和输出限制。`completed` 表示根退出 0 且 Job 已清空；它不采集每个子进程的业务退出码，调用程序仍须向上报告子任务失败。10 项 CPU 检查覆盖正常/非零退出、内存/输出限制、父进程先退及后续子任务超时。
- 已完成 YFINE 批次的待执行入口关闭，旧契约移到 `last_completed_execution_contract`，原始授权快照与哈希不变。用户的自主 GPU 研究授权仍保留；新批次需要新的具体输入、环境、资源和脚本版本契约，不能重新消费旧 attempt。
- 交接检查按实验对应的固定 Git 提交核对旧源码，避免代码升级被误认为历史证据损坏。本次损伤试验 r2 的四份来源在 `251986ee9a362c466a77124d5256fad7541eeff6` 与原哈希吻合。当前实现另外运行回归；不会把旧检查通过冒充新代码已验证。

Windows 行为依据：阅读了微软 [JOBOBJECT_BASIC_ACCOUNTING_INFORMATION 的 Syntax/Members](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information)，使用 `ActiveProcesses`；以及 [Job Objects 的 Managing Processes、Resource Accounting、Managing Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)，核对继承、计数和关闭时终止语义。阅读范围仅上述官方网页章节，日期 2026-09-25。

## 4. 后续研究安排

1. 对真实算子链明确输出误差预算的来源，先区分已知成分控制例和未收敛 FDTD；有预算后才能恢复相应相关诊断，不以一个统一绝对振幅门限删除弱事件。
2. 保留共同层、局部/弱目标、无目标负控联合评价；比较算子能力及跨网格变化，而不是先训练一个单一质量分数。
3. 原 YFINE 后续的 `dy=12.5 mm, dz=3.125 mm` 配对仍处于预算准备阶段。当前机器的 V4/CUDA 环境须独立核验，另一台电脑的 36 分钟耗时或约 7.3 GiB 整卡采样不能当作本机保证；本轮没有启动或扩展该批次。

核心回归现在为 157 项（原 136 + 方向诊断 21）。本轮成果是代码可靠性修复与评价可用性约定，不能表述为雷达处理性能提升。
