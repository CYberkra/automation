## 3. 版本追溯是本轮最有价值的结果

### 3.1 2025 年代码更接近 PDF 描述的导出方式

历史提交 `83072a5` 的 `src/lib/vna_controller.py:287`（`data_dump`）默认使用仪器 `CSV Formatted Data`、`Trace`、`Displayed` 导出；`src/lib/fluent_window.py` 中的采集 worker 调该接口逐道保存文件。

这条路径是让仪器输出已格式化曲线，代码本身没有在该环节重新构造频域到时域变换。结合 PDF 第 22 页的 `S21 Real` 显示和营山 CSV 的正负值，**“仪器内部时域变换 → Displayed 实部导出 → 提取/合并为标准 CSV”是有据、优先检查的来源假说**。尚未取得当时运行日志、原单道导出或准确版本，所以不记为已证明。

### 3.2 当前 ICZT 模块不能代替历史采集事实

Git 历史显示 `src/lib/iczt_processor.py` 在 `17e899b05ea2a8f31fc14e2790a93c6596c694fe`（2026-06-09）首次加入，晚于用户指定目录名的 2025-09。标准堆叠 CSV 写入器则在 2026-07-21 加入。不能用这些新增功能回填 2025 年数据的来历。

当前代码有两个不同路径：

- 仪器显示路径读取 FDATA，实际意义取决于仪器当时的显示、变换及校准设置。
- 自动 SFCW 路径读取复数 SDATA，执行 ICZT；支持 Kaiser β=6/8、Hann 等窗，时间轴使用含端点的 linspace。模块同时产生幅值、实部和虚部，但 worker 的主数据流选择**幅值/包络**。

因此，当前自动路径输出通常非负，不能未经说明拿它替代营山带符号实数输入。当前 UI 默认 300–3000 MHz、1001 点等只是软件默认值，也不是营山设置证据。ICZT 在配置回调中将时域点数设为频率点数，是软件选择，不是二者物理上必须相等。

### 3.3 仓库中还存在一个有用但有限的原导出样例

`src/从P9371B导出保存的一道A-Scan参考数据.csv` 的头部明确给出 `Time(s),S21 Real(U)`，记录日期为 2026-01-10；本轮解析 501 点、0–900 ns、间隔 1.8 ns，253 点为负。它提供了 **原仪器文件同时保存时间轴和带符号实部**的可检验证据；该样例轴与 T/(N−1) 一致。

但是其场景、频率设置和标定条件未知，且不是营山对应的原道；它不具有自由空间或已知反射体标定资格，也不能单独确认营山 700 ns 端点约定。精确时间轴优先从营山原导出取得，避免继续只靠标准文件头推测。

## 4. 为什么这会改变我们对“振铃”的处理

[Keysight 同系列 VNA 时域官方说明](https://helpfiles.keysight.com/csg/pxivna/Time/TimeDomain.htm)说明：时间曲线由频域响应变换而来，参考平面/校准、变换模式、频率步长、谱窗及门控都会影响输出；[FDATA/SDATA 官方说明](https://helpfiles.keysight.com/csg/pxivna/Programming/GP-IB_Command_Finder/Calculate/MeasureDATA.htm)区分显示格式化曲线与复数测量数据。因此，本项目看到的波列可能同时包含有限带宽变换的旁瓣、仪器/天线链响应和场景回波，不能预先全部归为单一的天线衰减振荡。

本轮只用构造频域响应 `exp(-j2π f·14 ns)`，在 20–170 MHz/501 点、0–700 ns/501 点上调用已读过的当前 ICZT 代码；没有使用实测数据拟合。五种窗的 Bluestein 与直接指数求和相对 L2 差为约 1–2×10⁻¹³，另核对 20 个 Python 标量直接和。这只确认该构造下的频时转换数值行为。

| 构造谱窗 | 全带尾窗 RMS / 早时峰（相对 40–140 ns） | v0.6 窄带 q（相对 45–70 ns） |
|---|---:|---:|
| 矩形 | 0.01402 | 0.01085 |
| Kaiser β=6 | 0.000402 | 0.02033 |
| Kaiser β=8 | 0.0000796 | 0.02221 |
| Hann | 0.000210 | 0.02055 |
| Blackman | 0.0000795 | 0.02273 |

注意：窄带 q 又经过 90–125 MHz 前后向带通和 Hilbert 包络。这个无额外天线拖尾的构造，在全带尾部减少时，q 反而可以变大；说明 q 不仅反映原始物理拖尾，还反映诊断滤波的响应及早时脉冲形状。不能仅靠 q 命中实测值来签认系统振铃重建。**这些数值不证明哪种窗是营山实测使用的，也不证明谱窗能解释全部实测振铃。**

## 5. 当前能推进什么，缺什么

可以先做的工作是**重建观测/导出链的候选并验证**，再决定是否需要额外振铃增广：以已知模拟频响控制例隔离谱窗、时间轴、实部/包络和延迟贡献，不动冻结奖励/训练/求解门，也不把输入域扩展为首版产品新分支。gprMax 的场强传递响应与仪器端口 S21 不是同一标定量；方法比较和归一化展示不等于二者的绝对幅值已适配。

最有价值的补充资料按顺序是：

1. 营山对应的**原仪器单道 CSV**（带时间轴、列名和头部）及**仪器状态文件/截图**：频率向量、Transform mode/window/β、时间起止、校准、电延迟、门控、IFBW、平均设置；以及实际提取/合并脚本。即使没有复数数据，这些也能明显收窄导出链。
2. 若当时留存了 S21 复数导出、s2p 或原采集记录，核对真实频率轴与实部/包络转换；本轮指定营山目录未见这些文件。当前 worker 能另存复数 sidecar，不能据此声称历史样本也有。
3. 为完整系统响应重建取得同设备同设置的自由空间/已知反射体记录，以及天线研制/校准原始幅相数据。只有名义天线增益或未知场景的一道参考曲线，仍不能完成系统分离。

对之前“资料不足”的结论应细化为：**并非毫无线索，已有资料能恢复不少采集链约束；完整、可信的仪器振铃重建仍缺准确历史状态和独立标定观测。** 当前不应继续以固定 107 MHz/73 ns 的形似作为验收依据。
