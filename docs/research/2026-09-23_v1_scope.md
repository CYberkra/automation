初版研究本场景下如何自动选算法、调参数和决定有必要的顺序，搜索空间只包含上述两类。以项目相关地下结构为保护重点；暂不引入检测器、成像或端到端去噪网络，也不将跨场景泛化作为首版验收目标。

## 2. 为什么适合从这两类开始

- 两类方法直接作用于 B-scan，结果能在输入域逐步比较，便于分清每一步的作用。
- 背景估计和增益强度都有明确参数，适合先做有限搜索，再训练快速配置选择器。
- 两类也能暴露核心评价问题：背景是否被压低、地层是否被误删、深部目标是否更可辨，以及残余噪声是否被过度放大。
- 功能范围缩小后，可以先证明“自动选择比固定配置有用”，再决定模型复杂度。先后顺序不必立即做成任意长度的 RL 流程。

## 3. 初始候选库（建议，尚未冻结）

| 类别 | 起步候选 | 可选择的参数 | 扩展顺序 |
|---|---|---|---|
| 背景抑制 | 不处理；全局均值道扣除；局部均值/中值背景；截断 SVD 背景抑制 | 窗口、作用区间、扣除强度、删除/抑制的分量数 | 先从均值法做基线，再比较局部估计与 SVD |
| 增益 | 不加增益；有上限的时间幂/指数曲线；AGC 对照 | 曲线参数、参考时间/样本、增益上限；AGC 窗及稳定项 | 先比较低参数曲线，再加入数据自适应增益 |

常数增益可作为对照，但在固定数据域中它同时缩放信号和噪声，不能单独算作信噪比改善。AGC 单列评价其幅度关系变化，不将它称作已标定的物理吸收补偿。时间参考不明确时使用明确的样本坐标，不自行重复零时或航高校正。

这里列出的是候选算法类别，未确定具体公式、参数范围、秩选择或增益上限；应在简单场景/输入尺度明确后形成算子契约。参考实现与方法资料见[第一轮研究](2026-09-23_uav_sfcw_autoprocessing.md)中的 GPRPy、RGPR 和 SGC/WNNM 文献。

## 4. 顺序：先建立简单基线，再检查必要的差异

起步基线采用：`输入 B-scan → 背景抑制或跳过 → 增益或跳过 → 数值结果`。这是一条便于归因的默认流程，不是已经证明最优的物理定律。

不应把所有顺序都视为不同方案。例如，设 `X` 为时间×道矩阵，`P` 为固定的道方向线性平均算子，背景扣除为 `B(X)=X(I−P)`；所有道共用的固定时间增益为 `G(X)=DX`。则：

`G(B(X)) = DX(I−P) = B(G(X))`。

在这一限定条件下，交换顺序的输出相同，训练顺序选择器没有额外收益。SVD 的数据依赖子空间、AGC 的数据依赖增益等通常不满足上述条件，再用实际输出比较决定是否纳入反向顺序。带自适应窗口、阈值、截幅或掩码时也必须重新检查，不能泛化上述等式。

## 5. 最小评价与推进

先准备少量简单层状、局部目标、弱反射和无深部目标场景。在同一场景上比较不处理、仅背景抑制、仅增益及两者组合，保存背景抑制后的中间结果和增益曲线。

评价分开回答：

1. 背景抑制是否降低了指定干扰，以及真实地下反射的到时/形态/幅度损伤。
2. 增益是否改善深弱目标的可辨性，以及残余背景/噪声、假事件和幅度失真的变化。
3. 自适应配置相对最优固定流程的收益，和选择开销/总耗时。

只有候选之间存在稳定、可学习的差异后，再用 gprMax 场景上的搜索结果训练配置选择/参数预测。随机噪声用于检查增益的放大风险，不增加独立去噪动作。实测尚无 clean 真值时不编造真实 SNR；同时报告保留结构和负控表现。

下一步应细化这两类的最小算子契约、参考输入和评价定义，而非恢复全流程开发。此次范围确认不等于已经启动正式仿真、训练或算法实现。

### 7.1 为什么先做特化

这是结合现有资料的工程判断：明确服务对象后，可以围绕实际输入、干扰和需要保留的响应设计实验，更快检验自动配置是否减少人工工作。领域相关数据值得重视：CR-Net 的研究表明其混合数据构造是方法的重要部分，但其目标与我们的结构保留需求不同，不能复制标签。[CR-Net 原论文摘要](https://arxiv.org/abs/2205.08135)

特化指围绕场景定义训练分布、候选参数和评价重点，不是记住某条测线或一套固定地质模型。尚不能由此断言特化模型必然优于通用模型；当前先不承担两者的比较任务。

### 7.2 首版要证明的结果

1. **背景抑制有用：**指定干扰降低，同时项目相关弱反射/界面未被系统性误删；真实断续和变化仍保留。
2. **增益有用：**约定的深弱响应更便于检查，或在已知衰减实验中实现补偿；同时报告噪声放大、幅度失真和负控，不能仅以亮度判定。
3. **自动选择有用：**与独立确定的固定流程及人工参考相比，在保真允许范围内改善结果或减少人工时间；如果固定流程足够好，如实保留结论。

指标沿用[评价协议](2026-09-23_v1_evaluation_protocol.md)，其保护 ROI 和分类型报告以本场景为重点。钻孔是稀疏地质约束，不是 clean 波形；“与钻孔相符”不能单独证明处理正确。

### 7.3 数据与独立验证

- 依据当前审计，营山 18 份 CSV 是 6 条命名测线的三功率版本，不能当作 18 份完全独立场景；同线各版本及派生窗必须同组。
- 当前不用实测测线训练、调参、确定奖励/ROI 或抽取背景用于混合数据。本阶段也不新增按具体钻孔/解释剖面拟合仿真；先依据公开文献及明确假设定义场景类型。
- 当前先按仿真地质母模型划分开发、验证和测试，再生成裁窗与变体。后期启用实测前，再审查资料关联和适配/验证角色，不先编造独立样本数量；此前审计及有限预览如实记录，不能称为从未看过的完全盲测。
- gprMax 训练母模型围绕本项目所需结构保护问题展开，包含合理参数变化、弱界面与负控；这些是假设场景，不是当前场地已核实的地质事实，也不按期待滑动面生成唯一正确输出。
- 雅安或其他测区的跨场地泛化不作为首版通过门槛；以后扩展时再单独设计。保留本场景内的独立检查仍然必要，因为模型选择本身也会过拟合。[Cawley 与 Talbot，JMLR 2010](https://www.jmlr.org/papers/v11/cawley10a.html)

### 7.4 接下来的具体产物

先整理一张“仿真场景—保留响应—干扰—参考定义—指标—预期反例”对应表，形成最小算子契约。先检查评价是否会奖励删掉弱地层或仅放大噪声，再考虑少量试算、固定流程与有限搜索对照，最后决定选择器。

此前建议的“测线—钻孔对应表”延期至实测阶段。这一步不预设某条反射就是滑动面，也不要求先完成延期的几何校正。系统导出链信息不足时，只限制系统适用性结论，不阻断明确假设下的数值机制验证。本次方向调整尚未启动仿真或训练。
